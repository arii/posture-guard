How it works

Posture Guard — the five-minute tour. Written for the demo, so you can answer every question on this page without leaving the app.

1. The pipeline, end to end

  1. Camera: Intel RealSense D400-series depth + RGB A worker thread pulls frames continuously into a latest-frame buffer (so the dashboard always shows the newest image, never a stale queue), with bounded startup retries and stalled-stream recovery. The depth stream doubles as a distance gate: you are only scored inside 0.6–2.5 m of the camera. This is the live video panel — the color image with the pose skeleton drawn over it.
  2. Pose landmarks: MediaPipe Pose Each color frame goes through MediaPipe's Pose model, fully on this machine's CPU. It returns 33 2D landmarks with per-landmark visibility scores. The skeleton overlay on the video.
  3. Four posture metrics From those landmarks we compute head forward (ear ahead of shoulder), trunk lean (shoulder-to-hip line from vertical), head tilt, and shoulder level — all angles, so they work for any body at any distance in the band. A metric is “bad” when it crosses its threshold; hysteresis (3°) stops it flickering at the boundary, and landmark visibility must clear 0.5 before a reading is trusted. Thresholds: head forward ±12°, trunk lean ±10°, head tilt ±12°, shoulder level ±6°. The four metric cards, each with its own target band.
  4. State machine Readings are smoothed over 0.3 s, then a small state machine decides: bad posture must hold for 2 s before a chime fires; a spoken prompt follows 10 s later if posture is still bad, repeating at most every 30 s; sitting well for a moment returns you to GOOD. The status pill in the header — it flashes amber when a reminder fires.
  5. Audio worker A queue-backed playback thread plays a short synthesized chime, then a spoken prompt rendered on the fly with pico2wave (espeak-ng as fallback) — one Linux paplay call per sound, on the USB audio sink it discovers. What you hear: chime, then voice. The dashboard's Test / Play / Speak buttons fire each stage by hand.
  6. Local dashboard A FastAPI server on your own machine streams the annotated video (MJPEG), pushes metrics over a WebSocket, and serves this page. Everything the UI shows — thresholds, status, audio health — is computed by the app and sent from it; nothing is hardcoded in the page. The whole dashboard you are looking at.

2. The model

Posture Guard uses MediaPipe Pose, the legacy Solutions API, pinned to >=0.10.14,<0.10.30 because the Solutions interface was removed from later pip releases. It runs fully in-process, on CPU — no GPU, no server, no model download at runtime. It gives us 33 2D body landmarks plus a visibility estimate per landmark.

Everything on top of the model is ours: the angle geometry, the thresholds, hysteresis, smoothing, the state machine, and the audio flow are plain Python you can read in this repo (scoring.py, state.py, audio.py). The model finds a body; the posture judgment is code we wrote. We plan to migrate to MediaPipe's newer Tasks PoseLandmarker API when we need features the legacy API can't give us — the pin above keeps the current build honest until then.

3. Privacy: what is recorded

Nothing is recorded, nothing leaves the machine. We verified this in the code before writing this page:

  • No video or metrics are ever written to disk. Frames are analyzed in memory and dropped. The only files the app creates are synthesized audio WAVs (the chime and the spoken prompt) in a temporary directory that the OS clears on reboot — no camera frames, no landmark data, no metrics.
  • No network calls to anything but your own browser. The codebase makes no outbound HTTP requests of any kind. The only network surface is the dashboard itself, and it binds to 127.0.0.1 (localhost) by default — not reachable from other machines.
  • No cloud, no third-party services. The pose model runs locally on CPU; the speech is rendered locally too. Unplug the network and everything keeps working.

You can also run it without a camera: a synthetic frame source keeps the dashboard alive with a live status line explaining why.

4. Where it came from

I built this end to end in a single day at the Obvious hackathon in San Francisco, November 13, 2026 — you're reading the write-up on the same day it shipped. The setup is the one real-world arrangement I sit at every day: a RealSense D435i on a shelf above my monitor, pointed down at my torso. Every part — camera thread, scoring, the reminder state machine, the audio queue, this dashboard — was written for this hackathon, driven by one goal: reminders that are calm, explainable, and quick to arrive when you slouch and quicker to stop when you don't.

5. Roadmap: embedded Linux

The long-term goal is to run Posture Guard on small embedded Linux hardware (a Pi-class board beside the desk) rather than a full desktop. This is intent, not something we've tested on target hardware yet. What already helps: the whole stack is CPU-only with no GPU dependency, the footprint is a handful of lightweight Python processes, and the system degrades gracefully (trusted metrics only, honest UNRELIABLE status) instead of failing hard. What needs work: packaging for a minimal OS image, headless operation without a desktop audio session, and a compute assessment to confirm the pose model's frame rate fits the board's budget.
